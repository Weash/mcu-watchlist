# MCU watchlist

A private watchlist of every Marvel Cinematic Universe feature film, on a
Cloudflare Worker. SvelteKit + Tailwind + D1, gated by Cloudflare Access.

## Architecture

- **Auth** — Cloudflare Access (Google SSO) sits in front of the Worker; the
  Worker verifies the Access JWT itself rather than trusting it is behind the
  gate. Ticks are keyed on the JWT's `sub` claim. `/admin` is additionally gated
  on `OWNER_SUB`.
- **Data** — D1, via Drizzle. `films` is the catalogue, `watches` is one row per
  (user, film) seen, `discoveries` is the review queue for the sync.
- **Rendering** — SSR with form actions. The page arrives with your ticks,
  counts and progress bars already correct, so there is no loading state.
  `use:enhance` makes a tick feel instant; it falls back to a full form post
  with JavaScript disabled.
- **Sync** — a weekly Claude routine, not a cron trigger. See
  [docs/sync-routine.md](docs/sync-routine.md).

Two deliberate ownership boundaries run through the whole thing:

- **TMDB owns** `title`, `release_date`, `poster_path`. **You own** `saga`,
  `phase`, `description`. The sync only ever writes the first group.
- **Phase colours live in the frontend**, not the database. They are design
  tokens chosen to work against the paper background — you would change them by
  editing a stylesheet, never by running an UPDATE.

`upcoming` is not stored. It is derived from `release_date > today`, so a film
becomes tickable on its release day with no deploy and no UPDATE, and the
"38 released films" count corrects itself.

## Local development

```bash
npm install
npm run fonts              # download the Latin-subset woff2 files (once)
cp .dev.vars.example .dev.vars
npm run db:migrate:local   # creates and seeds a local D1
npm run dev
```

Cloudflare Access is not in front of `vite dev`, so there is no JWT locally.
`hooks.server.ts` uses `DEV_USER_SUB` instead — gated on `dev`, a build-time
constant, so the branch is eliminated entirely from the production bundle. It is
deliberately **not** conditioned on a missing header, which would make any
Access misconfiguration an authentication bypass in production.

## Deploying

```bash
npx wrangler d1 create mcu-watchlist    # put the id in wrangler.jsonc
npm run db:migrate                      # apply migrations remotely
npm run deploy
```

Then set the secrets:

```bash
npx wrangler secret put OWNER_SUB      # see below
npx wrangler secret put TMDB_API_KEY   # TMDB v4 read access token
npx wrangler secret put SYNC_TOKEN     # openssl rand -hex 32
```

`ACCESS_TEAM_DOMAIN` and `ACCESS_AUD` are plain vars in `wrangler.jsonc` — fill
them in from your Access application's settings.

**Finding your `OWNER_SUB`:** deploy first, visit `/whoami`, and copy the `sub`
value. Delete `src/routes/whoami/` once the secret is set.

## Migrations

```bash
npm run db:generate        # after changing src/lib/server/db/schema.ts
npm run db:migrate:local
```

⚠️ `drizzle/0001_seed_films.sql` is a hand-written data migration, generated by
`npm run seed:generate`. Drizzle's journal does not know it exists and will
happily generate a schema migration with the same number — check for a filename
collision after every `db:generate`, and renumber the generated file (plus its
`meta/NNNN_snapshot.json` and the `idx`/`tag` in `meta/_journal.json`) if there
is one.

## Styling

Tailwind v4, configured entirely in `src/app.css`. The palette, the three font
families, and the type-scale additions live in `@theme`.

The six phase colours are in a separate `@theme static` block, and that matters:
they are applied by setting `color` inline on a phase container and letting
`border-current` / `bg-current` inherit it — the same `currentColor` mechanism
the original design used, where one value drives the checkbox border, its fill,
and the tag. Because that reference lives in a `style` attribute rather than a
utility class, Tailwind's tree-shaking cannot see it and drops the variables,
silently rendering four of the six phases black. `static` emits them all.
